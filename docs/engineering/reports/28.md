## Compatibility, deployment prerequisites and remaining risks

Reviewed upstream changes include stricter malformed-authority/responsive-image/meta-refresh sanitization; GET matchers accepting HEAD; narrower trusted-proxy private ranges; script/base URL handling; restored parent fragment router context; and host placeholders constrained in compiled matchers. HttpKernel also tightens mapped request payload formats. Existing regression and cached-runtime smoke checks cover current application behavior, not every deployment-specific proxy, sanitizer customization or future Symfony integration.

Deploy only after lead review, using PHP >=8.4.1 with required extensions and `composer install` from the reviewed lock. Operators must rebuild generated route/runtime caches with the patched code and coordinate code/vendor/cache rollout; old compiled route caches can retain vulnerable routing behavior. Verify actual proxy/header configuration and any custom sanitizer policies in the target environment. No deployment or local application config caching is performed here. Review [Composer audit guidance](https://getcomposer.org/doc/03-cli.md#audit), [Laravel 13 testing](https://laravel.com/docs/13.x/testing) and [Filament 5 guidance](https://filamentphp.com/docs/5.x/upgrade-guide) for the existing stack; this is no major-version migration.

This dependency patch changes no tables, migrations, foreign keys, trigger definitions or historical actors. Existing MySQL trigger/binlog deployment prerequisites still apply; no global database settings are changed. Test-time migration credentials belong only to CI's disposable schema; runtime application credentials remain separate. Authorization remains deny by default, with no new production/staging panel grant or tenant management route.

Audit is a time-bound advisory-feed check, not a proof of exploit absence or production readiness. No current application exploit was reproduced. A rollback to the base lock restores known vulnerabilities and needs separate reviewed risk handling; forward correction is preferable. No secrets/private owner records are included. Local environment files/keys, application database state, personal files, existing services and contributor work are preserved.
