## Implementation and security design

`ApproachAssignmentAccess::runFixture()` is a trusted PHP test-entrypoint boundary, never a public route/command. It accepts only testing, the exact named scenario, positive distinct actor identifiers, verified MySQL8.4 CI database/server UUID or actual SQLite `:memory:`, and no database URL. Context is stored in a WeakMap keyed by the **exact Request**, with exact connection/PDO and finally cleanup. Header, form, session or capability configuration alone cannot enable it. Capability recognition is temporary inside that boundary and restored afterward; normal capability grants remain empty. Local, staging, production and absent/mismatched contexts deny even with existing roles/permissions.

The actual Policy requires current membership/tenant binding, the unchanged structural authorization check **and** explicit current fixture assignments. A supplementary locking joined role/permission read inside the approved new access class prevents old RR snapshots from passing a committed structural revoke. It adds a refusal condition rather than replacing shared authorization. Query/list predicates use current explicit view assignments before search/count/order/pagination; creator and primary-unit relations confer no access.

The named issuer bootstraps only fictional Quality/contributor structural roles and four institutional fixture assignments. Quality creation contains a server-owned designated recipient plan. One transaction reuses existing CreateApproach rules and persists the resource plus seven explicit resource assignments and their audit. Quality receives view/metadata/contributor-revoke; the named contributor receives view/draft/version/audit. Quality gets no implicit draft/history grant; contributor gets no metadata/create grant; the issuer gets no content access. No general transfer, review, approval or delegation is activated.

Assignments start immediately and expire exactly24h later in UTC. The named issuer may revoke Quality's marker; the scoped Quality actor may revoke contributor resource assignments. Reads and writes re-evaluate current grants; the adapter rechecks after the callback before commit, rolling back a draft if expiry crosses that final boundary. Existing current-user/password and membership checks remain. No silent retry or cached-session privilege is introduced.

Grant/revoke events are transactional. Actual denied executions can record minimal same-tenant access_denied and deduplicated expiration_observed events **after** failed domain rollback, provided the actor/context remains verifiable. Policy/UI visibility queries write no denial events. Early shared-panel403 is verified through HTTP; no audit is fabricated for that excluded session boundary. Expiry enforcement does not depend on a scheduler or observation event.

## Database integrity and deployment portability

Two new, independently journaled migrations create `approach_assignments` and `approach_assignment_changes`. MySQL uses atomic per-table CREATE with inline indexes/FKs/CHECKs; SQLite creates equivalent structures transactionally. No new trigger, existing migration change, global database setting, package or CI edit.

Constraints seal TEST_ONLY/scenario/fixture namespace, finite operation/scope combinations, resource/initial-recipient rules, exact24h validity and complete revocation tuple. Unique scoped grants include a generated non-null scope key. Tenant/account/resource references are restrictive; event references include `(organization_id, fixture_id, assignment_id, subject_id)` to prevent cross-fixture/subject audit attribution. History is append-only through its model; model guards are not a claim of raw-SQL WORM storage.

Both reverse migrations check **both** new tables for any rows before any DROP. Populated grants/events refuse rollback without data loss. Original history protections remain. Handled missing-parent DDL failures leave no partial new table and retry normally; existing unjournaled objects are refused, not adopted/deleted.

Deployment operator prerequisites remain MySQL8.4 with enforced CHECK/generated-column/composite-FK support, schema DDL permissions and the already documented trigger/binlog privileges for existing migrations. Runtime HTTP must not use that operator. Error1419 behavior is still covered without SET GLOBAL or removal of integrity. A crash after successful CREATE but before the migration journal write still requires operator reconciliation; this change supplies no destructive automatic repair. These migrations are not an authorization to run against development/production data in this task.

The supplementary current read rejects committed role/permission revokes despite a demonstrably old nonlocking snapshot; membership/assignment variants and current list totals are also exercised. The ordered-write test lets a locked authorized draft commit before the waiting role revoker, then rejects the subsequent write. No retroactive cancellation or universal organization serialization is claimed.

Shared RoleManagement/TenantAuthorization and all other mutation ownership paths remain excluded. A complete operational lock graph, global deadlock/retry behavior and broader shared revocation semantics need separate approval and proof before an operational guarantee. The assignment model is deliberately concrete and named-fixture-only; it is not a production permission framework. Model immutability is not protection from a privileged database operator. An audit-store failure may fail the operation; it cannot grant access. Denials rejected before a trusted actor/tenant can be re-established have HTTP evidence, not invented tenant audit.
