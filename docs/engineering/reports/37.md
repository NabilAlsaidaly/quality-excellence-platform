## 6. MySQL Integration and T17 — BLOCKED

A dedicated isolated MySQL 8.4 test environment was provisioned under the approved environment-only authorization.

The first migration attempt failed with MySQL Error 1419 while creating a trigger under binary logging.

A later attempt used a temporary setting on the isolated instance only and restored the original setting afterward.

The T17 test body reached 12 assertions, but PHPUnit reported a teardown error when `DatabaseMigrations` attempted rollback.

The existing migration safety guard rejected rollback because account identity/recovery state existed:

`2026_11_05_000005_create_institution_password_reset_tokens.php`

The migration and protected `MySqlTestCase.php` were not modified. No manual deletion or reset of protected state was performed.

### T17 security finding

The characterization test uses two independent MySQL connections to the same disposable database.

It revokes the management permission through the second connection after Gate authorization and before the unit operation acquires its first organization lock.

The current operation still creates the unit and its audit record, although a subsequent Gate check denies the capability.

This demonstrates the Gate-to-write revocation gap.

**This is not a passing security result. T17 remains unresolved.**

The shared locking and authorization protocol is assigned to the engineering lead under Issue #58. No workaround or shared authorization modification was introduced in Issue #37.
