## Executive summary

حُسّنت واجهات الدخول المؤسسي وطلب استعادة الوصول وتعيين كلمة المرور وصفحة الحساب بالعربية RTL، باستخدام مكونات Blade الأصلية من Filament5: حقول وأغلفتها وأزرار ومجموعات fieldset. أُثبت تحميل الثيم والخط محليًا خارج اللوحة، مع استخدام الهوية البصرية القائمة دون إنشاء نظام واجهات أو مصادقة موازٍ.

أُنجزت في المتصفح رحلة خطأ الدخول، طلب الاستعادة برسالته العامة، فتح الرابط الموقّع، خطأ عدم تطابق التأكيد، تغيير كلمة المرور، الدخول بها، الحساب والخروج ثم رفض العودة بجلسة منتهية. تحققت قراءة قاعدة الاختبار من تغيير الحساب المقصود فقط وبقاء حساب المؤسسة الأخرى صاحب البريد نفسه دون تغيير. الحساب الاصطناعي غير المخوّل لم يحصل على رابط مساحة المؤسسة؛ الاختبار الآلي يثبت ظهوره فقط بالتفويض الاصطناعي المحدد ثم اختفاءه عند سحبه.

لم يتغير منطق الأعمال أو المصادقة أو السياسات أو المسارات أو قاعدة بيانات التطبيق، ولم تُنشر صلاحيات أو بيانات حقيقية. جميع الاختبارات القديمة باقية دون تعديل. هذا العمل لا يعتمد D002 أو ADR004 ولا يفتح الإنتاج أو staging.

## Asset strategy and visual verification

The shell uses `@filamentStyles` for installed native color/style/font assets and `@vite('resources/css/filament/admin/theme.css')` for the existing compiled theme entry. The four exact source lines ensure the identity views' utility classes are actually compiled. Browser resource timing verified the theme CSS, packaged Inter CSS and local font file all return200 from the same loopback origin. No external asset was requested.

`Filament::getPanel('institution')` is read only for existing visual settings. Palette variables are scoped to this standalone HTML document, without registering colors globally or making a panel current. Primary buttons receive that same existing palette through Filament's supported array-color API, so native contrast-slot selection sees the correct palette. The new HTTP test verifies the color registry, current panel, default guard and TenantContext remain unchanged by the public render.

Actual contrast measurements exposed two presentation issues: overriding CSS variables alone left the native button's shade map based on the default palette, and the native dark600 background/white text measured below4.5:1 for this palette/version. Corrected only the affected identity buttons: pass the existing palette and use existing dark700/hover800 utilities. No new palette or shared CSS rule. Final sampled primary-button contrast: **6.63:1 light,5.64:1 dark**. This is a measured control sample, not a full WCAG certification.

The shell uses the existing `filament:theme:mode` preference and system dark preference, with a small presentation-only initializer and optional existing CSP nonce. No authentication/session state is stored in localStorage. Native buttons/inputs/fieldsets remain ordinary HTML POST forms; no new Livewire component or scripts/framework is introduced. Font configuration is the existing packaged Inter/system fallback stack, not the preview-only Tahoma token or an external font.

All three surfaces were checked at375/768/1280 in light and dark modes: document scrollWidth equals viewport width in all18 combinations. Inputs and buttons measured44px high; Arabic RTL and LTR institution/email inputs verified. The native focus ring was visually inspected and measured after its75ms transition settled.
