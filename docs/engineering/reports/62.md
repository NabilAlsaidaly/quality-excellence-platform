## Code delivered

### Actual isolated intake/quarantine

`QuarantineTestFile` accepts a real UploadedFile only through an internal trusted test call. It refuses non-testing environments; actual SQLite memory or an explicitly identity-verified owned MySQL8.4 `quality_platform_ci` server is required. The local filesystem root must resolve inside the canonical testing-disk root, outside public storage. It reuses the existing Document context/metadata boundary without changing that Action or the original synthetic-stream storage contract.

Rules are explicit test inputs, without adopting the proposed30MB limit or a runtime whitelist. Detection uses actual bytes, not the browser's MIME declaration. Copying is bounded, destination names are generated and exclusively reserved, staged MIME/size/hash are verified, scanner exceptions/invalid results fail closed as unavailable, and post-scan mutation is rejected. Current tenant membership is checked again after scanning. Private JSON manifests persist the result; every result, including clean, has `servable=false`. No Document/DocumentVersion is created or promoted. Failures compensate only files exclusively reserved by that attempt; failed compensation requires inspection.

The scanner is an explicit harmless test closure. It is not a production AV service, queue, scan history, release policy or user upload endpoint. A receipt does not authenticate a download. No route/controller/provider exposes this Action.

### Review transition domain

New immutable domain values distinguish target/revision/tenant, pending/changes-requested/approved/superseded, actor and event time. A qualifying changed fingerprint opens a new pending review and preserves the prior decision; pending work is superseded. A no-op emits no new review/event intent. Creator/last-editor contributor identities are server-input requirements and cannot self-review. Invalid expected revision, repeated decision, immutable-revision tampering, foreign target and backward chronology fail.

Event intents contain only bounded identifiers/type/state, no body, reason or guessed recipient. Their hash is a deduplication input, **not durable outbox idempotence**. These objects grant no authority. A future Action must bind the current persisted revision, contributors and Policy inside the reviewed SQL transaction. Holding an old in-memory object is not protected against another connection; database-level review uniqueness/concurrency and publication are unimplemented.

### Initial maturity domain

`ApprovedStageAssessment` freezes the complete supplied scale, manually selected band and supplied question/answer/evidence snapshot data through immutable JSON. It requires an independently approved review value of the correct kind and exact fingerprint. It neither verifies actual reviewer authority nor validates persisted required-question/evidence eligibility; the future application transaction must do so.

`InitialMaturityCycle` accepts only the next fixed stage for the same institution/Approach; all five stages can advance even with the lowest approved category. Historical snapshots remain unchanged. Earlier-stage reassessment is outside this initial-cycle class: it cannot silently rewrite history or invent D014 continuation/reset behavior. No scale placement, exact percentage, midpoint, aggregate, API unlock or operational maturity UI is added.
