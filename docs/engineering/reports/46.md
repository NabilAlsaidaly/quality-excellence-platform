## Security and architecture review

The registered definition exists consistently across environments so Laravel route caches cannot omit its middleware identity. **Definition registration is not access authorization.** The earliest runtime gate returns404 outside local/testing regardless of APP_DEBUG, including a locally generated cache loaded under staging/production. Platform remains unregistered and its guard absent. `/admin` remains the existing development shell without ApproachResource; preview receives no live data.

Existing `/institution/login` and its normal account redirect remain. The account link calls the same canAccessPanel predicate as the protected panel. There is no second login, guard or permission engine. Native authentication middleware can run before the bridge because of Laravel priority; the reviewed subclass therefore checks the actual institution guard and delegates unauthorized guests to the existing login. The bridge reloads the provider account, checks active guard, server-side institution/password proof and actual membership/Policy, establishes context and restores it in finally. User input cannot select actor or authority.

Livewire persistent middleware executes its reconstructed-route proof pipeline before component work; it does not keep TenantContext alive throughout an action. Every ApproachAccess operation independently re-establishes and verifies scope within the existing locking transaction. After waiting for the lock it compares the current locked password to the validated session principal. Real password/membership changes and assignment revocation fail before persistence. Native hidden/visible state is insufficient: callMountedAction explicitly checks the named operation again, and the Action adapter reauthorizes inside the transaction. Revoked mounted saves return403, not Filament's silent no-op.

The exact native logout POST is intercepted after CSRF and delegates existing InstitutionEntry/BrowserAccountSession, preserving the one-browser/two-guard current-device contract and other-browser remember behavior. It works even after the business grant is revoked. Missing CSRF returns419; ordinary guests redirect to login (JSON unauthenticated requests receive401); invalid/current unauthorized principals403; foreign/malformed/numeric resources404; stale writes409. Safe Arabic conflict rendering is limited to the institution panel, including local debug mode, with no automatic retry or extra history.

No migrations or database privilege/configuration changes. Existing organization serialization, current locking reads, restrictive composite FKs, UNIQUE/CHECK, rollback/trigger safety and historical protections remain. Draft tokens are the latest revision external ULID or `none` under the same lock before the existing append Action. Old revisions are not edited. Audit/draft reads are independent grants; write permission alone cannot prefill confidential prior text. Existing raw SQL/operator access is not a WORM guarantee. Future durable assignments must define a compatible transaction/revocation protocol before operational use.

Owner search returns at most20 scoped ULID/name options, with escaped literal LIKE and a separately scoped selected label. A unit beyond100 is searchable and usable; no full preload or first100 truncation. Batch view-link hints verify shared actor predicates once and query scoped resources once; stale hints confer no detail/write authority.120 synthetic Approaches yielded35 queries for both page sizes1 and20 (SQLite adapter benchmark, approximately5.35/6.28ms). This measures that adapter and fixture only, not a whole-page query budget or production SLA.
